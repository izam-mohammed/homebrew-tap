# every formula and cask is styled, audited and installed by one command, locally and on every PR

## The ask

The repository standard asks for lint and format, tests, a coverage floor
of 90 % (target 95 %), and security checks (dependency audit, secret scan,
static analysis where it applies), all run by one local check command and
by CI on every PR, reusing the shared gate in `izam-mohammed/.github`.

What it means here: this tap holds one formula (`claim.rb`) and one cask
(`Casks/penpot-mcp.rb`), both generated by GoReleaser and pushed by the
release bot. There is no CI of any kind. Homebrew's own `brew style` and
`brew audit` are the lint, `brew install` plus the formula's `test do` is
the test, and the shared gate covers secrets and workflows. A 90 %
coverage floor is not applicable: there is no program code.

Built so far: `docs/built/BUILT-2026-10-22-1827.md`.

## Constraints

- The files say "generated by GoReleaser. DO NOT EDIT". A style or audit
  failure is fixed in the app's `.goreleaser.yaml` and released again,
  never by editing the file here.

## Alternatives

### Decision 1: what checks a formula or cask (two-way door)

Searched 2026-10-22: "homebrew tap CI brew audit brew style brew test-bot
GitHub Actions third-party tap", "brew style tap formula cask brew audit
GitHub Actions setup-homebrew"; docs.brew.sh BrewTestBot, a third-party
tap's workflow (bcomnes/homebrew-tap).

| Criterion | Weight | Baseline: nothing | `brew style` + `brew audit` | `brew test-bot` |
| --- | ---: | ---: | ---: | ---: |
| Performance efficiency | 40 | 5 | 4 | 2 |
| Fit to the ask | 35 | 1 | 4 | 5 |
| Reliability | 25 | 1 | 4 | 4 |
| **Weighted total** | **100** | **2.60** | **4.00** | **3.55** |

- Efficiency: style and audit read the files and, with `--online`, fetch
  URLs (4). test-bot installs, bottles and tests dependents, built for
  taps that ship bottles; this tap ships prebuilt archives (2).
- Fit: test-bot covers the whole lifecycle (5); style and audit miss only
  the install, which decision 3 adds (4).

**Chosen: `brew style` and `brew audit --strict`** on the tap, wrapped in
`scripts/check.sh`. Revisit if the tap starts building from source.

### Decision 2: how secrets, workflows and code are scanned (two-way door)

Searched 2026-10-22: "pre-commit.ci vs pre-commit/action GitHub Actions
run hooks on pull request"; the shared gate's README in
`izam-mohammed/.github`, the `repo-template` README.

| Must | Baseline: none | Shared gate (`security-scan.yml`) | gitleaks action alone | pre-commit hooks only |
| --- | --- | --- | --- | --- |
| A committed secret fails the PR | no | yes | yes | no (local only; bot pushes skip it) |
| **Survives** | no | **yes** | **yes** | no |

| Criterion | Weight | Shared gate | gitleaks action alone |
| --- | ---: | ---: | ---: |
| Performance efficiency | 40 | 3 | 5 |
| Compatibility | 35 | 5 | 2 |
| Security | 25 | 5 | 3 |
| **Weighted total** | **100** | **4.20** | **3.45** |

- Efficiency: four stages against one; exact minutes unverified.
- Compatibility: the shared gate is what the profile and site repositories
  already call.
- Security: zizmor lints the new workflow, which has a write-capable token
  nowhere but reads URLs from generated files.

**Chosen: the shared gate**, `ecosystem: shell` (the closest pack; there
is no Ruby one), pinned by commit SHA. Revisit if the gate gains a Ruby
ecosystem.

### Decision 3: whether each formula and cask is proved to install (two-way door)

Searched 2026-10-22: same queries as decision 1; the BrewTestBot docs
(install and test are the core of its lifecycle).

| Criterion | Weight | Baseline: no install | `brew install` + `brew test` on macOS and Linux runners |
| --- | ---: | ---: | ---: |
| Performance efficiency | 40 | 5 | 2 |
| Fit to the ask | 40 | 2 | 5 |
| Reliability | 20 | 3 | 4 |
| **Weighted total** | **100** | **3.40** | **3.60** |

- Efficiency: two runners per PR, macOS minutes cost the most (2).
- Fit: only an install shows a user's path works, including the cask's
  quarantine postflight on macOS (5).

Sensitivity: 10 points moved from fit to efficiency flips it (3.70
against 3.30), so it is fragile; kept, as the only check of what a user
does.

**Chosen: install and test on `macos-latest` and `ubuntu-latest`**, in
Phase 2. Revisit if runner minutes become a constraint.

## The decision

`scripts/check.sh` taps the checkout under a local name and runs
`brew style` and `brew audit --strict` on every formula and cask
(decision 1). `.github/workflows/check.yml` runs it on every pull request
and push to `main` with Homebrew's `setup-homebrew` action, and
`.github/workflows/security.yml` calls the shared gate (decision 2).
Phase 2 adds install and test jobs (decision 3). If the generated files
fail a rule today, the check starts from the rules they pass and the
failure goes to the app's GoReleaser config as a follow-up, never a
hand edit.

Dependencies: `Homebrew/actions/setup-homebrew` and the shared reusable
workflow, both pinned by commit SHA. No secret, no new permission beyond
the gate's `pull-requests: write`.

Standards: `docs/standards.md` (none yet; `brew style`, `brew audit` and
the install test through `sh scripts/check.sh` once Phase 1 lands).

## Security

What is protected: the formulae users install, and CI that fetches every
URL they name. Who reaches it: pull requests, and the release bot pushing
to `main`.

| Threat | Here | Handled by | Proved by |
| --- | --- | --- | --- |
| Tampering: a swapped archive | `url` changed without `sha256` | `brew install` verifies the sha256 | the Phase 2 install job fails on a mismatch |
| Information disclosure: a token committed | a hand edit adds a credential | gitleaks in the shared gate, blocking | the gate's stage 1 on the PR |
| Elevation of privilege: a workflow abused | file content reaching `run:` | `contents: read`, no `${{ }}` in `run:`, zizmor | zizmor reports no finding |

Data: none personal. Secrets: none used. Logged: URLs and versions only.
Checklist: SLSA build track and the CIS GitHub benchmark, editions to be
confirmed when built.

## Declined

- Nothing (decision 1): no check at all today.
- `brew test-bot` (decision 1): built for bottling taps; this one ships
  prebuilt archives, and it costs the most runner time.
- pre-commit hooks only (decision 2): bot pushes never run them.
- gitleaks action alone (decision 2): a parallel gate, no workflow lint.
- A 90 % coverage floor: no program code.
- A `site/` one-pager: the tap only delivers apps.
- A README banner plan: PR `#1` already carries it.

## What the tests hold

- `brew style` and `brew audit --strict` pass on both files, or the
  rules they fail are listed in `docs/standards.md` with the follow-up.
- `brew install` of the formula and the cask succeeds on macOS and Linux,
  and `brew test claim` passes (Phase 2).

## Follow-ups

- Bot pushes land on `main` without a PR, so the check reports after
  publishing. Moving GoReleaser to open PRs is a change in each app's
  repository.
