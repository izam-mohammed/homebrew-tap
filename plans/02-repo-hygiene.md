# the tap says how to report a security problem and is tagged with what it is

## The ask

The owner asked, on 22/10/2026, to "have dependabot in all of my repos" and
to "have proper security.md file for all of my repos". The tap is not a
product in itself, so the caller's list gives it no licence: it only
delivers other apps, each licensed in its own repository.

What `main` holds today: `README.md`, `claim.rb` (the formula for `claim`
from `izam-mohammed/claim-your-code`) and `Casks/penpot-mcp.rb` (the cask
for `penpot-mcp`). Both are generated by GoReleaser from those repositories'
releases and must not be edited by hand. There is no `.github/`, no
workflow, no package manifest and no `SECURITY.md`. The repository is
public, with GitHub private vulnerability reporting enabled. It had no
GitHub topics.

## Alternatives

No choice is open here: the licence is out of scope for this repository,
and with no workflow or manifest there is no update bot to pick, so the
plan follows the one approach the owner set for every repository.

## The decision

A repository setting and one file, no code:

- GitHub topics set from the README and the generated files.
- No Dependabot config: `main` has no workflow and no manifest, and
  Dependabot has no ecosystem for Homebrew formulas or casks; GoReleaser
  bumps them on each release. A `github-actions` entry is added when the
  first workflow lands (Follow-ups).
- `SECURITY.md` for a public repository: reports go through GitHub private
  vulnerability reporting; the tap only serves the latest version of each
  app, so only that gets fixes.
- No `LICENSE`, by the owner's list.

There is no rough cut: this is repository housekeeping with nothing to
use. New dependencies or permissions: none.

Security: no code, input, data, secret or dependency changes; the change
only adds a policy saying how to report a problem privately.

## Declined

- A `dependabot.yml` now: no ecosystem exists on `main` for it to watch.
- Hand-editing `claim.rb` or `Casks/penpot-mcp.rb`: GoReleaser overwrites
  them on the next release.

## Follow-ups

- When PR #2's checks add a workflow, add `.github/dependabot.yml` with
  `github-actions`, weekly, 7-day cooldown, one group.
