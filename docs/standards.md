# homebrew-tap: what every change passes

There is no check yet: no local command and no CI.
`plans/01-quality-gates.md` lands `sh scripts/check.sh` and the workflows
that run it. Until then, a change is done when its formula or cask was
generated by GoReleaser and installs.

## Toolchain

| What | Version | Pinned in |
| --- | --- | --- |
| Homebrew | user's | not pinned |
| GoReleaser | upstream project's | each app's `.goreleaser.yaml`, not here |

## Checks

| Check | Tool | Config | Command | Passing means |
| --- | --- | --- | --- | --- |
| Format and lint | none yet | | | `plans/01-quality-gates.md` (`brew style`) |
| Audit | none yet | | | `plans/01-quality-gates.md` (`brew audit`) |
| Install test | the formula's `test do` | `claim.rb` | `brew test claim` | runs `claim --version`; not run in CI |
| Secret scan | none yet | | | `plans/01-quality-gates.md` |
| Dependency audit | not applicable | | | no dependencies: formulae point at release archives with sha256 |

## Tests

No program code, so no unit tests and no coverage floor. A formula's
`test do` block is its test.

## Constraints

- Every file is generated by GoReleaser in the app's own repository and
  pushed straight to `main` by the release bot. Never hand-edit; fix the
  generator and release again.

## Conventions

- Commits: Conventional Commits for human changes (`docs(readme):` in PR
  `#1`), lowercase subject, no attribution lines. Bot commits keep
  GoReleaser's message.
